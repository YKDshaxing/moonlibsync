100% 本地浏览器 Web Worker 后台计算，绝不上传任何文件数据；导出的 .sig / .delta / rollback.delta 与 librsync rdiff 及 CLI 完全兼容。

ROLE A · RECEIVER 生成标准签名 (.sig)

接收方只需上传轻量 .sig 签名文件给发送方，无需暴露完整旧文件。

ROLE B · SENDER 生成增量差分 (.delta / .delta.gz)

发送方仅凭 .sig 与 NEW 文件即可算出标准 librsync .delta 与压缩后的 .delta.gz。

ROLE C · APPLY & VERIFY 应用补丁并校验还原 (自动解压 .delta.gz + 可选 Manifest 校验)

自动识别 RFC 1952 Gzip 帧并执行有界解压；提供 Schema 1/2 manifest 时将严格验证 basis / delta / result 三方 SHA-256。

通用产物剖析器（.sig · .delta · .delta.gz · .mbundle · .menc · Schema 1/2/3/4 JSON）

浏览器端 Schema 3 目录快照、移动检测、巡检与 .mbundle.gz 单文件打包

单文件归档打包 & 浏览器端解包验证（MLSBDL01 / .mbundle.gz）
支持 CopyFromBasis 0 字节复用、UpdateDeltaFrom 跨路径差分，解包时自动解压 Gzip 并逐文件验证 SHA-256。
自动执行 --exclude 匹配、--detect-moves 内容指纹移动检测、POSIX 路径安全校验与跨平台 ASCII 大小写冲突检测。

有界 RFC 1952 Gzip 安全防线实测（Zip-Bomb · 尾随数据 · 截断流）

1. Zip-Bomb 解压炸弹拦截

现场生成 256 KiB 零字节高压缩炸弹（仅约 300 B），以 4 KiB 解压上限执行有界解压，验证引擎在超出预算瞬间中断并报 LimitExceeded。

—

2. 尾随垃圾字节拒绝

在合法单流 Gzip 尾部追加 1 字节多余载荷（0x42），验证单流严格帧校验立刻返回 TrailingData。

—

3. 截断流 / 尾部缺失拒绝

截去 RFC 1952 尾部 CRC32/ISIZE 校验的最后 1 字节，验证解码器严格报 TruncatedInput，绝不静默返回不完整数据。
