## Commit 19：拥有独立生命周期的准备索引

开发入口 prepare_signature 直接复用本页原有 parse_signature、build_signature_index 和工作单位，不重写排序。PreparedSignature 私有保存真实签名字节数与最终 SignatureIndex，所有必要元数据由它们获取；外部接口无内部字段、构造器、setter、可变预算或查询入口。排序临时数组不进入返回对象，摘要仍只在解析记录中，不再复制出第二份摘要索引。它不持有 basis 或原始签名缓冲，不推断真实旧文件/尾块长度。

一次准备拥有一次 MatchWork；初始化3n在两个索引数组分配前预收，其后每比较和写入各收费1，重复记录不去重，完整UInt32弱键按无符号顺序、同键按原序号排序。工作耗尽仍为 LimitExceeded；准备对象不保留余额。原一次性 delta 的索引、扫描及指令共享预算未动，检查CLI也未增加命令。

独立边界样例：零记录成本0；单记录3；两条同键9；八条同键60；128条同键1728；四键[MAX,0,0x80000000,0]成本25（12初始化+8写入+5比较）。需要量少1拒绝、恰好及多1通过；零记录的负工作配置返回 InvalidOptions。白盒以原16夹具的完整块/真实短尾查询准备索引，以实际basis独立确定重复块的最早序号；真实弱/强摘要确认保持原行为。宽偏移6442450941经过内部匹配返回而未窄化。

对象内部使用只读，但不声明跨线程安全。尚无 PreparedSignature::delta，不将这些准备/查询测试作为重复生成或性能收益证据；复用生成与有限对照基准留给 Commit20。下文保留原匹配实现阶段的契约。

## 结构与稳定顺序

build_signature_index只接收已经parse_signature验证的Signature和一次上层操作创建的MatchWork，不接收basis，不访问文件系统。索引持有该只读签名和排序后的记录序号，避免复制全部强摘要；内部调用方必须保持已验证记录只读。临时排序存储为两个长度n的Int32数组，空间O(n)，没有按UInt32全集分配的表。

采用迭代归并排序，按完整UInt32 weak_sum再按原输入序号排序；二分定位第一个弱校验候选，按升序遍历，因此多个前缀匹配时返回最小原序号。不依赖Map顺序或哈希冲突行为。所有比较、余项复制均收费，不留下退化的无计量排序/插入路径。

match_signature_window接收索引、当前窗口BytesView、调用者提供的弱校验和共享预算。本笔测试的查询弱校验均来自真实RabinKarp；未来由扫描器提供。空窗口直接None、收费0，不产生零长度匹配；超过block_len先返回InvalidOptions("window_len")，不查询索引。有效窗口1..block_len，无弱候选时不计算强摘要；有候选时只计算一次strong_sum，逐候选比较全部已配置摘要字节。

结果只含原记录序号、UInt64 nominal_offset和当前窗口真实长度，没有COPY或delta指令。选中后复核宽整数序号乘块长与已存偏移一致，并检查offset+length不溢出。签名没有basis长度/真实尾块长度，最后一条不预设短块长度；短窗口用其真实字节确认。不能认证一个实际旧文件或保证范围可执行，也不把记录数乘块长当作basis长度。短摘要碰撞只是已保存前缀相同，不等于内容绝对相同。

## 工作单位（算法工作量，非CPU周期）

MatchWork::new先Limits::validate，remaining取max_match_work，合法范围及默认256*1024*1024保持不变。上层一次创建后传给索引和后续多次查询，辅助函数不补满。以下单位定义为有固定上界的算法动作，控制分支及常量次数元数据访问包含于对应动作，完整扫描调度不在本笔范围。

| 阶段 | 收费 |
| --- | --- |
| 索引初始化 | 3*n，保守覆盖每记录处理和两个索引槽；两次数组分配之前整体预收；n为Int32，Int64乘3安全 |
| 归并 | 每次有界词典序比较1单位（最多三个原始比较及常量元数据读取）；每个写入1单位，包括剩余项复制 |
| 二分查询 | 每个定位探测1单位，先收费再读记录；区间终点之外不读记录 |
| 弱组存在性 | 当定位点在数组内时，存在性检查1单位；不存在不收摘要费用 |
| 强摘要 | 1单位固定初始化/收尾，加window_len个输入字节单位；全部预收后只调用一次 |
| 候选 | 每条遍历1单位，包含弱组结束探测及受检元数据计算；遇到下一组也计1单位 |
| 摘要比较 | strong_sum_len单位，比较前全额预收；即使早期字节不等也不退费 |

这些固定动作涵盖边界计算、数组访问和循环控制的常量工作，不声称等同精确指令数或通用堆内存上限。归并宽度倍增与边界相加使用剩余长度证明安全。无候选不哈希；同一窗口多候选不重复收取摘要费。预算不足返回LimitExceeded，单次未成功收费不改remaining，但此前已扣额度绝不退还；失败不修改签名或已建索引。新独立操作可创建新预算，不能在辅助函数里重置共享预算。解析及未来扫描/COPY/delta/patch的完整工作预算不在本笔范围。

固定边界样例：单记录索引3单位，3字节窗口/16字节摘要查询23单位，总26恰好通过。三条相同弱键的已排序记录建索引18单位；第三条才成功的查询58单位（2定位+1存在性+4摘要+3候选+48比较），总76恰好通过，75在末条比较前拒绝并留下已扣费后的15单位。多次查询共同耗尽同一预算，不免费重试。

## Commit 10 扫描共享预算扩展

Commit 7 的索引、排序、二分、摘要及候选单位全部保持不变。公开 delta 只创建一个 MatchWork，经索引和整个扫描传递；不在循环、窗口重建或失败处理中重新创建。解析器继续受签名字节/记录/块预算控制，不把原解析优先级改写为工作收费。

| 扫描动作 | 新增收费（工作前预收） |
| --- | --- |
| 非空窗口首次建立或匹配后重建 | 1 个状态初始化单位 + 真实窗口长度个 update 字节单位 |
| 每次窗口循环 | 1，涵盖有界调度、视图/元数据读取和位置推进；未命中也必须收费 |
| rotate | 3：1 个滚动操作 + outgoing/incoming 两字节 |
| EOF rollout | 2：1 个滚动操作 + outgoing 一字节 |
| 指令追加或合并尝试 | 1，涵盖固定次数的元数据检查、视图构造、受检宽整数运算、最短大小估算及一次槽位写入/追加 |

不逐字节重新计算整块弱校验；匹配后重建的实际输入字节收费。每次窗口的强摘要与候选收费继续由 match_signature_window 执行，有弱候选时只哈希一次。保留最小原序号的候选选择，不因期望与 rdiff 字节一致而改变规则。最后 encode_delta 仍执行原预检和编码，编码缓冲受 max_delta_bytes 控制；本笔不声称已审计全库总堆内存或所有资源退化。

预先验证新文件长度同时不超过 max_new_bytes 和 max_output_bytes。累积器保存新文件视图，连续未匹配字节合并；COPY 仅在输出相邻且 previous_offset+previous_length==next_offset 时合并，两个求和均受检。追加前检查合并后命令数及含 magic/END 的编码大小，替换末条时先扣除其旧编码大小。连续块可在 max_instructions=1 下合并成功，重复引用相同偏移则不能合并。宽度跨界（literal64/65、COPY255/256）计入增量大小检查。失败无 literal 回退，不退款、不补充预算。

固定新样例：单个 abc/3/16 的完整匹配消耗 32（原索引3、初始化4、调度1、原查询23、追加1）；31拒绝。三个攻击者构造的同弱键记录，第三个摘要匹配时总82（原索引18+初始化4+调度1+原查询58+追加1）；81及78拒绝。空索引扫描 abc：初始化4+三次调度/追加/rollout共12，总16，15拒绝。这些是算法单位，不是 CPU 周期。空新文件仍解析签名，但无需索引或扫描，工作预算0可成功。

扫描仅观察签名和新字节，无法验证真实 basis 区间或身份。签名没有尾块长度，不猜测尾块在新文件中间的尺寸；可令其成为 literal。EOF 才以实际缩短窗口确认短块。短强摘要或恶意签名可能给出错误候选，正常验收使用独立签名及对应 basis 检查实际 COPY 范围和内容，应用仍应在格式外校验完整内容。
