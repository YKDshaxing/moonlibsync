# Commit 20：PreparedSignature 有限进程内对照

本机结果没有稳定的总耗时优势。复用确实省去每次签名解析与索引建设，但本组输入的扫描/摘要成本占主要部分，准备本身较短；六组总计中有三组复用中位数较慢，所有组的范围都有重叠。不能从这些样本推导其他硬件、数据、目标、复用次数或文件系统上的加速承诺。

## 固定对象、环境与命令

测量前固定 `tests/benchmarks/prepared-config.json`：64 KiB/1 MiB，K=1/4/16，2048/32，预热2轮、正式7轮。每组在同一个Native进程中执行9个成对轮次，偶数轮先一次性、奇数轮先复用。每轮复用路径重新prepare一次，再调用K次；不存在每次起产品CLI重新准备的替代测量。

旧字节来自SHAKE256(domain + ASCII(size) + /old)，逐字节与127按位与；domain为moonlibsync-prepared-commit20-v1。第i个目标按i%4循环：中部(size/2+17)替换64字节、前插32字节、中部删除64字节、相同文件。替换/插入第j字节=128+((i+j)%128)。同一size的各K采用同一old与目标前缀，不根据结果挑选样本。生成器及失败/缺轮统计自检在普通CI运行。

环境：Ubuntu 24.04 / WSL2 Linux 6.6.87.2-microsoft-standard-WSL2，glibc2.39，AMD Ryzen 9 8940HX，16个可见逻辑CPU、8核/2线程；WSL可见内存10427232256字节。输入/输出在本次新建/tmp目录（ext4），路径记录在manifest。GCC/cc 13.3.0，固定moonc 0.10.20+65efd5b93、moon/moonrun 0.1.20261104，锁定mooncrypt0.4.5与core。参考为librsync2.3.4/e364852674780e43d578e4239128ff7014190ed3，真实二进制路径、哈希和版本均记录。

实际Linux运行命令（使用项目隔离Linux工具链及固定参考工具）：

```bash
export MOON_HOME="$PWD/.toolchain/linux"
export PATH="$MOON_HOME/bin:$PWD/.toolchain/reference/cmake-wheel/cmake/data/bin:/usr/bin:/bin"
python3 scripts/benchmark_prepared.py
```

脚本先以当前 `moon build --help` 核对release参数，实际执行 `moon --target-dir _build/benchmarks-prepared/build build probes/prepared --target native --release`。计时驱动是专用参考适配器，不是新增产品CLI；只接收SIG、NEW与结果目录，不接收basis。

实测ELF：`/mnt/d/project/moonlibsync/_build/benchmarks-prepared/build/native/release/build/probes/prepared/prepared.exe`；SHA-256 `c2721a4bbf8d40c9181e36b097b4ad822da93b5d95afe58443c89541b329c81c`。测量时HEAD为 `7351eba44b8dd7a13987ceefe2be7c2769b4dc29`，dirty=true（本笔待提交的实现）。这不是最终干净同SHA重测；最终交付记录逐项复核manifest中的运行库/驱动/构建配置/依赖锁哈希，并关联最终SHA与必需CI。后续测试、工具隔离与文档编辑没有改变被测Native源码或配置，旧Commit15基准与0.1.0归档未覆盖。

## 计时与正确性边界

使用固定core/bench的单调时钟，单位微秒，保留Double原始结果；每次生成单独计时，准备也单独计时。每轮总计从调用路径开始到最后一次生成结果收集后实际读取时钟，包含本路径的循环、嵌套计时与结果数组追加；复用总计包含本轮真实prepare。没有把独立中位数相加冒充总计。对象/结果离开函数后的释放不在截止时间内。编译、输入准备、进程启动、文件I/O、字节对照和所有恢复验证均在这些时间窗外。

驱动在每轮两路径结束后核对全部生成字节相等；Python严格检查实际delta指令内容/COPY范围，固定rdiff逐份恢复并对照独立new。包含预热输出，共756份计时产物恢复；额外原16个签名夹具和同进程16目标组共有32份非计时恢复，各自单列，均通过。基准产物均COPY >= old_bytes-4096，未用纯literal冒充复用。原496用例/3968恢复矩阵保持另行统计。失败、进程非零、未完成轮次或非有限时间不得进入成功统计；raw样本先记incomplete，恢复通过后才记validated。

仅对7个正式轮次报告中位数与[min,max]，无性能通过阈值。没有清理CPU/磁盘缓存，不称为冷盘性能；没有测量RSS、堆峰值、CPU周期或统计显著性。

## 驻留结构与证据

64 KiB的对象保留32条记录、1024字节强摘要payload和32个最终序号（Int32 payload128字节）；1 MiB对应512条、16384字节强摘要payload及2048字节序号payload。另有记录中的弱校验/序号/UInt64名义偏移、签名标量元数据、对象/数组头及运行时开销，不能把上述payload和当成实测对象堆大小或RSS。原签名字节、排序临时数组、MatchWork、new或上次输出不由对象保留；多个对象分别占用存储。基准驱动自身还持有输入、时间与结果数组。

原始证据在独立忽略目录 `_build/benchmarks-prepared/`：manifest.json（硬件/工具链、source/dirty、Native源码范围哈希、配置、二进制、每组长度与输入SHA-256）、measurements.json（54个成对轮次及全部逐次时间/验证状态/实际delta大小与COPY）、summary.json、commands.log、interop-report.json。临时二进制输入/产物验证后清理，按固定配置可重建；不提交大量二进制。`--interop-only`使用独立子目录interop-check，避免覆盖本次完整计时证据；普通CI仅保留32次非计时互操作证据。

索引复用的正确性由调用路径、索引/记录引用、独立逻辑预算及恢复证明；墙钟不是复用成立的证据。新增API仅为开发源码，注册表0.1.0不含它；没有性能优化、预算提高、线程安全或版本发布结论。
